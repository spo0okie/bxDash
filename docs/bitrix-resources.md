# Подключение библиотек Bitrix

И в DEV, и в готовой сборке браузер открывает `index.html`. После авторизации
Bitrix фронтенд запрашивает `GET portal/resources` по базовому адресу `apiUrl`.
Например, при `apiUrl: '/reviakin/back/api/'` запрос идёт на
`/reviakin/back/api/portal/resources`.

API использует пролог и эпилог Bitrix. Ответ содержит CSS, внешние скрипты и
inline-настройки `BX` в порядке вывода портала. Фронтенд выполняет скрипты
последовательно и подключает каждый внешний файл один раз в документе дашборда.
Статические JS и CSS используют обычный HTTP-кеш браузера. Для запроса ресурсов
используется тот же origin, что и для дашборда.
Страницы старых карточек внутри iframe загружают свои зависимости. Для доступа к
`parent.BX` и `top.BX` у дашборда и задачи должен совпадать origin. Новую
`TaskFullCard` дашборд монтирует в SidePanel из ресурсов, подключённых на старте.
[Документация вывода ресурсов Bitrix](https://dev.1c-bitrix.ru/api_help/main/reference/cmain/showheadstrings.php)

## Профиль Bitrix

По умолчанию `auto` выбирает `modern`, если доступны API расширений и
конфигурации `main.popup` и `main.date`. Для остальных установок выбирается
`legacy`.

| Профиль | Подключение |
| --- | --- |
| `legacy` | `CJSCore::Init` для библиотек старого Bitrix и его служебные JS-файлы |
| `modern` | С новой карточкой регистрируются `main.core`, `main.sidepanel` и `tasks.v2.application.task-full-card`. При наличии также регистрируются расширения меню результатов в чате. Bitrix сам подключает их зависимости. На современных версиях со старой карточкой используются `main.core`, `main.popup`, `main.date` и `CJSCore::Init('sidepanel')`. |

При необходимости перенесите настройки прежнего `portal.config.php` в массив
`$bitrixResources` в `back/conf.php`. Ключи `profile`, `extensions`,
`coreExtensions` и `scripts` задаются там же. Списки переопределяют
значения своего профиля. Принудительный `modern` на установке без необходимых
расширений возвращает HTTP 500. [Пример конфигурации](../back/conf.example.php)

## Обновление размещения

1. Обновите каталог `back/` и фронтенд. В DEV обновите исходники Vite.
2. Уберите `bitrixResources.portalUrl` из локальных конфигов. Для обычной
   загрузки достаточно `apiUrl` на том же домене. Явный
   `bitrixResources.scripts` переопределяет загрузку из API, а `scripts: []`
   отключает подключение библиотек.
3. При публикации сборки установите индексом `index.html`. Если на сервере
   остались прежние `index.php` и `portal.config.php` фронтенда, удалите их
   после переноса параметров в `back/conf.php`.

В Network проверьте ответ `portal/resources`. Ожидается HTTP 200 и HTML с меткой
`bxdash-portal-assets`. Затем проверьте `typeof BX.ready` и действия в карточке
задачи на обеих версиях. На современном портале дополнительно проверьте
открытие SidePanel и обновление карточки после его закрытия.

`node tools/bitrix-portal-test.cjs` проверяет маршрут на подставных порталах,
в том числе выбор профиля, переопределение списков и отказ для анонимного
запроса. [Схема размещения](deployment.md)
