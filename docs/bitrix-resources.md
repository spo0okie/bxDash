# Подключение библиотек Bitrix

Общая схема размещения frontend/API в файловой системе портала и последовательность
инициализации: [развёртывание bxDash](deployment.md).

## Рекомендуемый режим: страница портала

1. Выполнить `npm run build` и разместить **содержимое** `build/` в каталоге
   сайта Bitrix. Пути бандлов должны соответствовать `base` в `vite.config.js`.
2. Открывать `index.php` этого каталога явно. Наличие `index.html` обязательно:
   PHP читает его как шаблон готовой сборки, а не запускает второе приложение.
   Порядок DirectoryIndex на сервере не меняется автоматически.
3. При необходимости скопировать `portal.config.example.php` в `portal.config.php`.
   Этот конфиг должен находиться рядом с опубликованным `index.php`.

`index.php` подключает служебный пролог Bitrix, регистрирует зависимости и выводит
их JS/CSS в head до запуска React. Шапка и меню сайта не подключаются.
Конфигурация `config.priv.js` и авторизация приложения продолжают использоваться.
PHP-страница также использует текущую браузерную сессию портала: вход через REST
сам по себе не заменяет вход в портал для просмотра его страниц в iframe.

### Совместимость версий

`profile = auto` проверяет наличие `Bitrix\Main\UI\Extension` и конфигураций
`main.popup` / `main.date`. При их наличии выбирает modern, иначе legacy.
Можно принудительно задать профиль; недоступный modern возвращает 500,
а не пытается незаметно смешать две реализации.

| Профиль | API и исходный набор |
| --- | --- |
| legacy (в том числе 2017) | `CJSCore::Init`: ajax, json, ls, popup, date, fx, webrtc, dd, tooltip, timer, window, autosave; служебные session.js, utils.js, rating_like.js, dd.js |
| modern | `Extension::load`: main.core, main.popup, main.date; `CJSCore::Init`: sidepanel |

Пути к кешу `kernel_main` не задаются: установленный портал сам формирует ресурсы
и зависимости. Для конкретной карточки могут понадобиться дополнительные
расширения: `extensions`, `coreExtensions` и `scripts` задаются серверным конфигом.
Это исходные наборы для интеграции, а не подтверждение работы всех действий
карточки на любой версии портала. Синтаксис PHP-точки входа совместим с PHP 5.

Ресурсы родительской страницы нужны для обращений к `parent.BX` / `top.BX`.
Сама страница задачи в iframe должна подключать собственные зависимости.
Доступ к BX родителя требует одинакового origin у bxDash и страницы задачи.

## Статический режим

При открытии `index.html` PHP не выполняется. Без настройки используется прежний
список файлов 2017 года, включая его привязанный к сайту путь кеша.
Для другой установки список можно полностью заменить в `config.priv.js`:

```js
bitrixResources: {
	scripts: [
		// Реальные URL установленного портала в порядке зависимостей.
	],
},
```

Пустой `scripts` отключает загрузку. Скрипты подключаются один раз и последовательно;
при ошибке загрузка останавливается и появляется уведомление с URL.
Существующий `window.BX` не сбрасывается. В режиме portal статический список
не используется, поэтому библиотеки не подключаются повторно.

## Проверка после публикации

Локально: `node tools/bitrix-portal-test.cjs` проверяет выбор API, переопределение
списков и порядок вывода HTML с подставными API. Unit-тесты загрузчика входят
в `npm test`. Для PHP 5 дополнительно нужен запуск на старом портале:
локальный `php -l` выполняется современным PHP и не доказывает совместимость.

На обеих установках открыть `index.php`, проверить выбранный профиль и отсутствие
404/ошибок JS, затем открыть задачу и проверить меню, даты, редактирование,
сохранение и вложенные окна. Проверить запрос и ответ сохранения, а также
обновление карточки dashboard после закрытия iframe. Локальные тесты с подставным
Bitrix API не заменяют эту проверку на реальных порталах.

Документация: [расширения](https://docs.1c-bitrix.ru/pages/framework/extensions.html),
[вывод ресурсов](https://www.dev.1c-bitrix.ru/api_help/main/reference/cmain/showheadstrings.php),
[SidePanel](https://www.dev.1c-bitrix.ru/api_help/js_lib/sidepanel/start.php?print=Y).
