# Статистика заявок

Кнопка 📊 в верхней панели открывает широкое модальное окно. В отчёт входят все сотрудники из `users.order` (роль `user`), включая сотрудников без заявок. Выбор сотрудника на основной доске не меняет область отчёта. Направления, SLA и подотделы для группировки или отбора не используются.

Выберите месяц или диапазон до года, способ отбора («Созданы за период» / «Закрыты за период») и дату состояния («На конец периода» / «На момент загрузки»), затем нажмите «Показать». Нажатие на показатель открывает список соответствующих заявок. Строка списка раскрывается в расчёт времени и интервалы пауз. CSV выгружает сводку или расшифровку.

## Правила

- Рабочие сутки — 24 часа в рабочие календарные дни расписания Inventory. Пока календарь не загружен, применяется пн–пт без праздников; это указано в окне.
- Время выполнения — рабочее время от создания до завершения за вычетом рабочей части отложенности. Пересечения пауз объединяются, границы обрезаются сроком заявки, выходные не вычитаются дважды.
- Среднее отдела — сумма времени всех закрытых заявок / число закрытых. У сотрудника без закрытых заявок показывается прочерк.
- Завершение — `DATE_CLOSE` Bitrix либо последний ответ техподдержки в статусе решения 9/10, если заявка не отложена. В отличие от старого отчёта штатное закрытие не зависит от автора последнего сообщения.
- «Просрочено» — открытые и закрытые заявки, у которых время без пауз строго больше 2 рабочих суток по SLA организации. Для закрытых берётся время до завершения, для открытых — до даты выбранного состояния. Ровно 2 суток не является нарушением. Старый порог отчёта (5 суток) не используется.
- Сохранены исключения категорий 52/55, статуса 58, внутренних обращений группы 6 и ручного списка исходного отчёта. Тестовые заявки распознаются по отдельным словам TEST/ТЕСТ, а не по подстрокам «тестирование»/latest. Исключённые заявки видны отдельно с причиной.
- История пауз получается через `CTicket::GetMessageList` по маркерам «ОБРАЩЕНИЕ ОТЛОЖЕНО» и «ОБРАЩЕНИЕ ВОССТАНОВЛЕНО ИЗ ОТЛОЖЕННЫХ».

Срез прошлого периода использует доступные даты закрытия и пауз. Ответственный, категория и статус являются текущими. Повторные открытия и ранее принятые решения без полной истории статусов не восстанавливаются: такой срез не является полным историческим снимком Bitrix.

## Публикация

Обновить фронтенд-сборку и файлы:

- `back/app/ctl/controller_ticket_statistics.php`;
- `back/app/models/ticket_statistics.php`;
- `back/app/models/ticket_statistics_rules.php`;
- `back/app/models/ticket_hold_intervals.php` (общий с расчётом карточек).

Таблицы и миграции не нужны. Доступ к общему отчёту разрешён администраторам и членам группы техподдержки. Правила можно переопределить массивом `$ticketStatisticsRules` в существующем `back/conf.php`; значения по умолчанию находятся в `ticket_statistics_rules.php`.

API: `ticket_statistics/get?from=2026-09-01&to=2026-09-30&mode=created&users=1,2`. Проверка прав выполняется до выборки. Фильтры по датам используют [официальный API CTicket::GetList](https://dev.1c-bitrix.ru/api_help/support/classes/cticket/getlist.php).

## Локальная проверка

`npm test -- --watchAll=false --runInBand`, `npm run build`, `node tools/check-undeclared.cjs`, `php tools/ticket-hold-test.php`, `php tools/ticket-statistics-test.php`.

Для визуальной проверки реального компонента без портала запустить Vite с `vite.verify.config.js` и открыть `/reviakin/z2/tools/ticket-statistics-preview.html`. Это изолированные тестовые данные; страница не входит в production-сборку и не обращается к порталу. Производственный API требует проверки после публикации на PHP 5.
