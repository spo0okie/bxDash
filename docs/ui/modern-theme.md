# Тема Modern — спецификация

## 0. Назначение и читатели

Документ — единый источник правды для оформления темы `modern`. Описывает **общий подход**: какие визуальные средства используются, что ими кодируется, где и в каком порядке они применяются. Конкретные значения цветов/размеров приведены, но вторичны — первично здесь система правил. При сомнениях в реализации сверяемся с этим документом, а не друг с другом.

Аудитория:
- разработчик, который правит `src/Themes/modern/tokens.css`;
- разработчик, который добавляет новый тип элемента или статус;
- ревьюер, который проверяет, что предложенный визуал не противоречит системе.

## 1. Цели темы

Приложение — **диспетчерский экран ИТ-отдела**. На одном экране одновременно отображаются десятки карточек разных типов в разных статусах, распределённые по колонкам пользователей и временным периодам. Тема `modern` должна обеспечивать:

1. **Мгновенное опознание ТИПА** элемента (задача / заявка / работа / план / напоминание) периферическим зрением, не считывая текст.
2. **Быстрое опознание СТАТУСА** при прицельном взгляде на карточку.
3. **Различимость карточек** между собой при плотной упаковке (≥10 карточек в колонке).
4. **Минимальную утомляемость** при многочасовом наблюдении.
5. **Однообразный визуальный язык** — одни и те же средства всегда означают одно и то же.

Чего тема НЕ делает:
- не пытается быть красивой ради красоты в ущерб различимости;
- не вводит уникальные стили для отдельных типов «потому что так выглядит лучше» — все типы следуют одной схеме разметки.

## 2. Визуальная иерархия (что важнее)

Порядок убывания приоритета. Каждый следующий уровень читается только при пристальном взгляде:

| Уровень | Что кодирует           | Чем выражается                                  |
|---------|------------------------|-------------------------------------------------|
| 1       | **Тип** элемента       | Цвет фона карточки + 4px вертикальная полоса слева |
| 2       | **Статус** элемента    | Модификация фона + опционально 1px overlay       |
| 3       | **Подсветка** (hover/parent/child) | Outer ring 2px поверх карточки           |
| 4       | **Алерты/обновления** (updates badge, alert, flash) | Маленький бейдж/анимация    |
| 5       | **Приоритет** (для задач) | Точка-индикатор 6×6 px                         |
| 6       | **Метаданные** (дедлайн, статус-текст, исполнитель) | Текст в footer, opacity 70%   |

**Запрещено:** одно и то же кодировать двумя средствами одновременно (например, статус — и фоном, и левой полосой). Один смысл — одно средство. Это правило главное и нарушать его нельзя.

## 3. Анатомия карточки (общая для всех типов)

Любая карточка — это `li.userItem` (или его nested-вариант, см. §6). Её каркас фиксирован:

```
┌──┬───────────────────────────────────────────┐
│▌ │  ▔▔ alert badge (top-right, абс)         │
│▌ │                                            │
│▌ │  Card body text                            │
│▌ │  More content                              │
│▌ │  ┌──────────────────────────────────┐      │
│▌ │  │ optional nested card (TaskLink)  │      │
│▌ │  └──────────────────────────────────┘      │
│▌ │  Footer: ●●●  deadline  status            │
└──┴───────────────────────────────────────────┘
 ▲    ▲                                          ▲
 │    │                                          │
 │    └─ Card body: padding 2px, font 12.5px      │
 │                                                │
 └─ TYPE STRIPE: 4px solid type-color, всегда     │
    присутствует на ЛЕВОМ КРАЕ.                   │
                                                  │
 Outer ring (hover/parent/child) ─────────────────┘
   рисуется через box-shadow ВНЕ карточки,
   не съедает внутреннее пространство.
```

Жёсткие правила анатомии:
- **Левый край** — всегда занят 4px полосой типа. Никакие статусы туда не пишутся.
- **Top/right/bottom края** свободны для статусных оверлеев и outer ring.
- **Внутреннее пространство** заполнено только текстом и иконками, никаких декоративных полос внутри тела карточки.
- **Бордер карточки** — 1px solid `--surface-divider` всегда. Не зависит от типа и статуса.
- **Скругления** — `0`. Везде.

## 4. Кодирование ТИПА (уровень 1)

Каждому типу присвоен **один цвет** и **один тон фона** (тёмная цветная плашка с этим цветом в основе). Выбраны 5 максимально различимых цветов:

| Тип    | Цвет (hue)   | Hex (полный)  | Фон карточки (saturation ~30%) |
|--------|--------------|---------------|-------------------------------|
| Task   | slate        | `#94a3b8`     | `#2a3142` (нейтральный)       |
| Job    | amber        | `#f59e0b`     | `#3d2e10` (тёплый)            |
| Ticket | blue         | `#3b82f6`     | `#15203a` (холодный)          |
| Plan   | violet       | `#a855f7`     | `#261743` (фиолетовый)        |
| Memo   | yellow       | `#facc15`     | `#3d2f0c` (жёлтый)            |

Правила:

- **Левый wedge 4px** — всегда полный цвет типа (из колонки «Цвет»).
- **Фон карточки** — приглушённый тон того же цвета (из колонки «Фон карточки»). Эти 5 фонов **попарно отличимы** периферическим зрением: тёплое (job/memo) vs холодное (ticket/plan) vs нейтральное (task), плюс уникальные hue.
- Цвет wedge и цвет фона связаны единой палитрой — это не декоративная пара, а ОДИН маркер типа в двух местах.
- Внутри типа цвет wedge **не меняется** (даже у закрытых задач или негативных). Тип не меняется со статусом.
- Если когда-нибудь добавится 6-й тип — он получает свой уникальный hue, выбирается так, чтобы быть отличимым от существующих 5.

## 5. Кодирование СТАТУСА (уровень 2)

Статус выражается **изменением фона карточки** + опционально **1px горизонтальной полосой сверху** для критичных состояний. Никаких полос справа, никаких рамок-обводок (кроме hover/parent/child — это §7).

### 5.1. Универсальный шаблон статусов

| Статус                     | Что меняется                                                                                                  |
|----------------------------|---------------------------------------------------------------------------------------------------------------|
| **base** (без статуса)     | Фон = `--TYPE-bg-base` (см. §4). Полос нет.                                                                   |
| **closed** (выполнено)     | Фон = `--TYPE-bg-closed`: тот же hue, но **темнее и desaturated** (~50% saturation от base). Текст приглушённый. Никаких полос. |
| **active / activeNow**     | Поверх base — 1px **success-stripe** (`#22c55e`) сверху карточки.                                              |
| **pending / closeMe**      | Поверх base — 1px **info-stripe** (`#3b82f6`) сверху + лёгкий info-tint фона (~10%).                           |
| **negative / failed**      | Фон = base + 25% danger-overlay → визуально красно-кровавый. 1px **danger-stripe** (`#ef4444`) сверху.         |
| **dimmed / dragging / dimmedOut** | `opacity: 0.6`. Фон не меняется.                                                                       |
| **alert** (ошибка серверная) | Накладывается danger-tint поверх + анимация `shake`. Шейк уже определён в `UserCell.css`.                   |
| **flash** (мигание)        | Анимация `flash` (success). Уже определена.                                                                    |
| **updating** (loading)     | Спиннер в правом верхнем углу. Уже определён через `:before`.                                                  |

Правила:

- Цвет stripe сверху — это всегда **семантический статусный цвет** из §8.1, не цвет типа. Это сделано специально: тип читается слева, статус — сверху, два разных «канала».
- closed-варианты затемняют фон, а не показывают полосу-индикатор «закрыто». Закрытое = тусклое.
- Статусные комбинации (например, `closed.negative` для задач) разрешены: фон определяется *более сильным* статусом (negative > closed), а stripe сверху берётся от того же сильного статуса.

### 5.2. Маппинг статусов на типы

| Тип    | Возможные статусы        | Особенности                                                  |
|--------|--------------------------|--------------------------------------------------------------|
| Task   | base / activeNow / closeMe / closed / closed.negative / dimmedOut | Все 6 универсальных статусов. |
| Job    | open / closed            | open = base, closed = closed-вариант с success-tint фоном (выполненная работа сама по себе хорошее событие). |
| Ticket | red / green / blue / closed | red/green/blue — варианты `pending`-стиля: 1px stripe сверху соответствующего цвета (danger/success/info), фон = base. closed — closed-вариант. |
| Plan   | denied / authorized / authorized.{unknown,partial,failed,complete} | denied = `text-decoration: line-through`, фон не меняется. authorized = elevated (фон чуть темнее, как у closed-task). Прогресс (unknown/partial/failed/complete) кодируется 1px stripe сверху в muted/warning/danger/success цветах. |
| Memo   | open / closed × expanded/compact | open = base (тёплый жёлтый), closed = closed-вариант с success-tint фоном (выполненное напоминание). expanded/compact — UI-режим, не статус, к маркировке отношения не имеет. |

**Plan не использует левую полосу-прогресс**. Это исключение из текущего classic-поведения. В `modern` плановый прогресс кодируется по общему правилу — stripe сверху. Левая полоса всегда занята цветом типа (фиолетовый wedge). Это сохраняет единообразие.

Так как `Plan.css` сейчас использует `border-left: <color> solid 8px` для прогресса, при реализации темы нужно будет переписать эти правила под общую схему (или ввести фоллбек-токен, чтобы classic не сломалась).

## 6. Nested карточки (TaskLink, TicketLink внутри Memo)

`MemoCard` рендерит markdown с упоминаниями задач и заявок (`[[T123]]`, `[[I456]]`) — они отображаются как `span.userTaskLink` / `span.userTicketLink` ВНУТРИ memo. Они тоже карточки, и тоже должны следовать общей системе.

Правила nested:
- **Wedge типа сохраняется** — 3px (вместо 4px) слева в цвете типа упомянутого элемента (Task slate / Ticket blue).
- **Padding** уменьшен пропорционально (1px вместо 2px).
- **Бордер** — 1px solid `--surface-divider`, как и у обычной карточки.
- **Текст** — наследует `--text-primary` темы (не `black`/`white` хардкод).
- **Статусы nested-карточек** считываются ТОЛЬКО как closed/active. Закрытая упомянутая задача — затемнённый фон (тот же `--task-bg-closed`). Active task — 1px success-stripe сверху как обычно. closeMe / negative для упоминаний не показываются (избыточный шум).

Это решает ту проблему, что на текущем скриншоте упомянутые в memo задачи имеют «другой язык» (border, две левые полосы, mini-card-внутри-card). После приведения к общей системе они выглядят как просто более компактные обычные карточки.

## 7. Подсветка карточек (hover / parent / child)

Это не статусы и не тип — это указание на отношения с курсором/выбранной задачей. Они не должны менять кодирование типа и статуса.

Реализация — через **outer ring** (box-shadow вне карточки):

| Состояние | Цвет outer ring | Толщина |
|-----------|-----------------|---------|
| hovered   | `--sem-success` (`#22c55e`) | 2px     |
| parentTask | `--sem-warning` (`#f59e0b`) | 2px     |
| childTask | `--sem-info` (`#3b82f6`) | 2px     |

Правила:
- Ring **не съедает** внутреннее пространство (через `box-shadow: 0 0 0 2px <color>` или `outline`).
- Ring **не закрашивает** содержимое карточки — фон, текст, type-wedge остаются без изменений.
- Ring может комбинироваться с любым статусом.
- Только одна подсветка одновременно (parent взаимоисключает hover, child взаимоисключает hover).

## 8. Палитра

### 8.1. Семантические цвета (для статусов и accent-маркеров)

Используется компактный набор из 6 цветов. Один цвет = одно семантическое значение, переиспользуется во всех компонентах.

| Назначение    | Hex        | Использование                                                  |
|---------------|------------|----------------------------------------------------------------|
| `--sem-success` | `#22c55e` | activeNow, closed-job, online-user, IDLE-phone, plan-complete  |
| `--sem-warning` | `#f59e0b` | open-job (тип), away-user, RINGING-phone, plan-partial, parent-ring |
| `--sem-danger`  | `#ef4444` | negative-task, closed-failed, unavail-user, INUSE-phone, plan-failed, ticket-red, severity-4-alert |
| `--sem-info`    | `#3b82f6` | closeMe-task, ticket (тип), pending-states, child-ring, severity-1-alert |
| `--sem-accent`  | `#a855f7` | plan (тип), closed-tasks-counter                              |
| `--sem-muted`   | `#64748b` | offline-user, UNKNOWN-phone, closed-task-stripe, plan-unknown |

Семантика проста: **зелёное всегда хорошо/идёт, красное всегда плохо/опасно, синее всегда «обработано/информация», янтарное всегда «нужно внимание», фиолетовое — мета-объекты, серое — нет данных/выключено**. Диспетчер обучается этому за 5 минут и потом не теряет фокуса.

### 8.2. Цвета типов

Берутся из §4. Они **не пересекаются** со статусами по hue (slate ≠ muted, амбер job≠warning только формально hue одинаков, но контекст разный — type vs status разделение поддерживается местоположением: тип всегда слева, статус сверху).

### 8.3. Поверхности

Три уровня глубины:

| Токен                       | Hex        | Где                              |
|-----------------------------|------------|----------------------------------|
| `--surface-page`            | `#0a0d12`  | body, фон страницы                |
| `--surface-app-bar`         | `#161a22`  | шапка, sidebar, поисковая панель |
| `--surface-card-base`       | depend on type | базовая карточка (см. §4)        |
| `--surface-card-closed`     | depend on type | приглушённый вариант             |
| `--surface-card-elevated`   | `#2a3142`  | UserCellHeader, dropdown, modal contents |

### 8.4. Текст

| Токен              | Hex        | Применение                       |
|--------------------|------------|----------------------------------|
| `--text-primary`   | `#f1f5f9`  | основной текст                    |
| `--text-secondary` | `#cbd5e1`  | вторичный (footer, дедлайн)      |
| `--text-muted`     | `#94a3b8`  | приглушённый (closed-task текст) |
| `--text-on-overlay`| `#f1f5f9`  | поверх overlay (auth form)       |

Правило: **никогда не используем `color: black` или `color: #fff` напрямую в CSS компонентов** — только через токены. На цветных бэкграундах текст должен быть `--text-primary` (с подходящим text-shadow если нужно).

## 9. Типографика

| Параметр        | Значение                                         |
|-----------------|--------------------------------------------------|
| Базовый шрифт   | `Inter, "Segoe UI", system-ui, sans-serif`      |
| Моноширинный    | `"JetBrains Mono", "SF Mono", Menlo, Consolas`  |
| `--font-size-base` | `12.5px` (плотнее classic 12px)               |
| `--font-size-sm`   | `11.5px` (footer, мелкие метки)              |
| `--font-size-md`   | `13.5px` (заголовки модалок, поиск)          |
| `--font-size-lg`   | `16px`   (UserCellHeader счётчики)           |
| `--font-weight-bold` | `600` (не `700`, в Inter 700 слишком жирный) |

Моноширинный применяется к: счётчикам в `UserCellHeader`, дедлайнам, временным меткам, ID-номерам в `ConnectionStates`. Это даёт диспетчеру выравнивание чисел по колонкам — числа быстрее сравниваются глазом.

## 10. Геометрия

| Параметр              | Значение  |
|-----------------------|-----------|
| Все `--radius-*`      | `0`        |
| `--space-1..5`        | `2/4/6/10/14 px` (плотная сетка)  |
| `--border-width-thin` | `1px`     |
| Толщина type-wedge    | `4px` (карточка), `3px` (nested) |
| Толщина status-stripe сверху | `1px` |
| Толщина outer ring    | `2px`     |
| Бордер карточки       | `1px solid var(--surface-divider)` |

`--surface-divider` — единый цвет для всех 1px бордеров между карточками. Хорошая видимость на любом цветном фоне типа: `#475569` (slate-500). Достаточно светлый, чтобы отделить карточки на фоне `#0a0d12`, но не пересиливает type-wedge.

## 11. AntD интеграция

Применяется `theme.darkAlgorithm` — массовое перекрашивание ~600 внутренних AntD-токенов. Поверх:

```js
{
  algorithm: antdTheme.darkAlgorithm,
  token: {
    colorPrimary:    '#3b82f6',  // = --sem-info
    colorSuccess:    '#22c55e',  // = --sem-success
    colorWarning:    '#f59e0b',  // = --sem-warning
    colorError:      '#ef4444',  // = --sem-danger
    colorInfo:       '#3b82f6',
    colorBgBase:     '#0a0d12',  // = --surface-page
    colorBgContainer:'#1c2230',  // нейтральный card-bg
    colorBgElevated: '#2a3142',  // = --surface-card-elevated
    colorText:       '#f1f5f9',
    colorBorder:     '#475569',
    borderRadius:    0,
    fontFamily:      Inter,
    fontSize:        12.5,
    controlHeight:   28,
  }
}
```

Все цвета AntD **берутся из той же палитры**, что и кастомный CSS — ни одного «AntD-only» цвета. Это исключает рассогласование тонов между Modal/Dropdown/Tooltip и кастомными карточками.

## 12. Прочие компоненты

### 12.1. UserCellHeader (счётчики над колонкой)

- Фон: linear-gradient `#2a3142 → #1c2230`. Это «крышка» колонки, заметно темнее карточек, но светлее body.
- Счётчики 6 шт., цвет — соответствующий семантический:
  - closedTickets — `--sem-info-strong` (`#60a5fa`)
  - openTickets — `--sem-danger-strong` (`#f87171`)
  - closedJobs — `--sem-success-strong` (`#4ade80`)
  - openJobs — `--sem-warning-strong` (`#fbbf24`)
  - closedTasks — `--sem-accent-strong` (`#c084fc`)
  - openTasks — `#f1f5f9` (нейтральный, обычные задачи без выделения)
- Шрифт счётчиков — моноширинный 16px bold.

### 12.2. UserItem (плашка пользователя в шапке)

Состояния присутствия (ABSENT / WEEK_ABSENT / TWO_WEEK_ABSENT) — фон-tint:

| Состояние         | Фон                                |
|-------------------|------------------------------------|
| ABSENT            | `rgba(239, 68, 68, 0.40)` (red 40%) |
| WEEK_ABSENT       | `rgba(245, 158, 11, 0.40)` (amber 40%) |
| TWO_WEEK_ABSENT   | `rgba(245, 158, 11, 0.22)` (amber 22%) |
| online (hover)    | `--sem-success-soft`               |

Точки статусов (online/away/unavail/offline) и phone-status — 6×6 px, цвет = соответствующий семантический.

### 12.3. UserAlerts (severity badges)

5-ступенчатая шкала:

| Severity | Bg          | Text       |
|----------|-------------|------------|
| 1        | `#3b82f6` (info)    | `#ffffff` |
| 2        | `#f59e0b` (warning) | `#1a1208` |

| 4        | `#ef4444` (danger)  | `#ffffff` |
| 5        | `#b91c1c` (critical)| `#fee2e2` |

Контрастность каждой ступени — AAA по WCAG.

### 12.4. Periods (временные полосы)

| 2      | `#10b981` | white     |
| 3      | `#06b6d4` | dark      |

## 13. Что считать «правильно реализованным»

Когда тема `modern` соответствует этой спецификации — выполнено всё:

- [ ] Все 5 типов карточек имеют 4px wedge слева в цвете типа (включая closed-варианты).
- [ ] Все 5 типов имеют свой характерный фон (не один и тот же тёмно-серый).
- [ ] Закрытые карточки видно как «потускневшие версии своего типа» — wedge остаётся, фон затемняется.
- [ ] activeNow/closeMe/negative — кодируются 1px stripe сверху, не справа, не слева.
- [ ] Hover/parent/child — outer ring 2px, не закрашивает фон.
- [ ] Nested карточки (TaskLink в Memo) подчиняются той же системе (3px wedge, тот же бордер).
- [ ] Plan-progress (unknown/partial/failed/complete) кодируется 1px stripe сверху, левая полоса — фиолетовый type-wedge.
- [ ] Все радиусы 0.
- [ ] Никаких `color: black` / `color: white` в компонентном CSS — только через токены.
- [ ] AntD-цвета совпадают с CSS-токенами темы.
- [ ] Все семантические цвета (success/warning/danger/info/accent/muted) переиспользуются согласно §8.1.

## 14. Что требует изменений в общем CSS (не только в tokens.css)

При реализации этой спецификации придётся изменить **структурный CSS**, а не только токены:

1. **Plan.css** — `border-left: <color> solid 8px` для прогресса заменить на `box-shadow: inset 0 1px 0 <color>` (top stripe). С токенами по умолчанию для сохранения classic.
2. **Task.css** — `li.userTask.activeNow {border-left: 4px solid var(--task-stripe-active-now);}` заменить на `box-shadow: inset 0 1px 0 var(--task-stripe-active-now)` для modern (через токен). Альтернатива — `--task-stripe-active-now-render` отдельным токеном, который в classic = border-left, в modern = box-shadow.
3. **Ticket.css** — red/green/blue (`border: solid 2px <color>`) заменить на 1px top stripe для modern. Аналогично через двух-токенную схему.
4. **TaskLink/TicketLink (внутри Memo)** — текущие правила накладывают свой border-radius/background — переписать на единую систему через токены.

Эти изменения не должны ломать classic. Стратегия — двойные токены: `--X-classic` (border-left/border) и `--X-modern` (box-shadow inset top), при этом `--X` = одно из них в зависимости от темы. Или переключатель через `[data-theme="modern"]` селектор в самих CSS-файлах компонентов.

Конкретный путь реализации обсуждается перед началом работы.

## 15. Открытые вопросы для согласования

Перед реализацией нужно зафиксировать:

1. **Plan progress на 1px stripe сверху vs левой полосе** — спецификация настаивает на верхней полосе, но diagnost у пользователя был привычен к левой полосе. Уверены, что меняем?
2. **Mid/high priority — точки или цветной текст?** Сейчас в classic: точки 6×6 + цветной текст. Modern наследует. Подтверждаем, или хотим что-то одно?

4. **Memo open** — оставляем как «sticker» (тёплый жёлтый фон + memo-shadow с offset)? Или уравниваем с остальными карточками?
5. **Ticket red/green/blue** — действительно ли заменяем 2px-обводку по периметру на 1px-stripe сверху? Это изменит привычный вид заявок.
