# Тема Modern — спецификация

## 0. Назначение и читатели

Документ — описание текущего оформления темы `modern`: какие визуальные средства используются, что ими кодируется и какие конкретные значения сейчас в `src/Themes/modern/tokens.css`. Это **снимок реализации**, синхронизированный с кодом — при расхождении истиной считается код, документ обновляется под него.

Аудитория:
- разработчик, который правит `src/Themes/modern/tokens.css`;
- разработчик, который добавляет новый тип элемента или статус;
- ревьюер, который проверяет, что предложенный визуал не противоречит системе.

## 1. Цели темы

Приложение — **диспетчерский экран ИТ-отдела**. На одном экране одновременно отображаются десятки карточек разных типов в разных статусах, распределённые по колонкам пользователей и временным периодам. Тема `modern` должна обеспечивать:

1. **Мгновенное опознание ТИПА** элемента (задача / заявка / работа / план / напоминание) периферическим зрением, не считывая текст.
2. **Мгновенное опознание ОТКРЫТОСТИ** (open / closed) — рабочая лента отделяется от истории с первого взгляда.
3. **Быстрое опознание СТАТУСА** при прицельном взгляде на карточку.
4. **Различимость карточек** между собой при плотной упаковке (≥10 карточек в колонке).
5. **Однообразный визуальный язык** — одни и те же средства всегда означают одно и то же.
6. **Стилистическая узнаваемость**: компактная плотная сетка, малые радиусы, угловой clip-path-срез у каждой карточки — общий «тон» интерфейса.

## 2. Визуальная иерархия (что важнее)

Порядок убывания приоритета. Каждый следующий уровень читается только при пристальном взгляде:

| Уровень | Что кодирует                            | Чем выражается                                                              |
|---------|-----------------------------------------|------------------------------------------------------------------------------|
| 1       | **Тип** элемента                         | **Цвет фона** карточки. Уникальный hue для каждого типа.                    |
| 2       | **Открытость** (open / closed)           | Hue фона разный для open и closed одного типа — закрытая задача синяя, открытая slate-серая и т.д.|
| 3       | **Статус** (activeNow / closeMe / negative / ticket-red/green/blue / plan-progress) | 4px полоса СЛЕВА в семантическом цвете (success/warning/danger/info/muted)  |
| 4       | **Подсветка** (hover / parent / child)   | **Инверсия:** фон карточки заменяется яркой семантической плашкой, текст становится тёмным |
| 5       | **Алерты / обновления** (updates badge, alert, flash) | Бейдж в углу / анимация фона                                  |
| 6       | **Приоритет** (для задач)                | Точка-индикатор 6×6 px + цветной текст подписи                              |
| 7       | **Метаданные** (дедлайн, статус-текст)   | Текст в footer, opacity 70%                                                 |

**Запрещено:** одно и то же кодировать двумя средствами одновременно (например, статус — и фоном, и левой полосой). Один смысл — одно средство. Это правило главное и нарушать его нельзя.

## 3. Анатомия карточки (общая для всех типов)

Любая карточка — это `li.userItem` (или его nested-вариант, см. §6). Каркас фиксирован:

```
┌─┬─────────────────────────────────────────┐
│▌│ Card body text                          │
│▌│ More content                           ╲│
│▌│ ┌──────────────────────────────────┐    ╲
│▌│ │ optional nested card (TaskLink)  │    │
│▌│ └──────────────────────────────────┘    │
│▌│ Footer: ●●●  deadline  status        ╲ │
└─┴────────────────────────────────────╲────┘
 ▲                                       ╲
 │                                        clip-path: срезанный нижний-правый угол
 │                                        (7px карточка, 3px nested)
 │
 └─ STATUS STRIPE: 4px слот на левом крае.
    - open без подстатуса → полосы нет;
    - activeNow / closeMe / negative / ticket-red/green/blue / plan-progress
      → 4px solid в семантическом цвете.
    Тип сюда НЕ пишется (тип — это фон).
```

Жёсткие правила анатомии:
- **Тип** карточки = **цвет фона**. Никаких type-полос, иконок или рамок.
- **Левый край** — слот для 4px полосы СТАТУСА (см. §5). У карточки без подстатуса полосы нет, левый край = край фона.
- **Бордер карточки** отсутствует (`--border-width-thin: 0`). Разделение карточек через `margin: 2px` и контраст фон-страницы / фон-карточки.
- **clip-path-срез** правого нижнего угла. Универсальный для всех карточек modern: `--cut: 7px` для основных карточек, `3px` для nested TaskLink/TicketLink. Это визуальная подпись темы — карточка похожа на «талон» или «бирку».
- **Скругления** — `--radius-md: 2px` (минимальные, почти прямые). Полное отсутствие радиусов невозможно из-за clip-path-эффекта углов.
- **Padding `.content`** — `1px 0 1px 3px` (плотная сетка).

## 4. Кодирование ТИПА (уровень 1)

Тип кодируется **только цветом фона карточки**. Цвета подобраны так, чтобы 5 типов были попарно различимы периферическим зрением — разный hue, разная температура, заметная насыщенность. Closed-вариант каждого типа отличается от open не просто яркостью, а **отдельным hue**, маркирующим «выполнено».

| Тип    | Open                                       | Closed                                  |
|--------|--------------------------------------------|------------------------------------------|
| Task   | светло-серый `#d6d6d6` + тёмный текст `#444444` | яркий синий `#367bf7` + светлый текст     |
| Job    | оранжевый `#f59910`                        | яркий зелёный `#00a13c`                  |
| Ticket | тёмно-серый `#666`                         | cyan `#0acae1`                           |
| Plan   | фиолетовый `#551b95`                       | приглушённый фиолетовый `#2e1f4f` (authorized) |
| Memo   | тёплый жёлтый `#5a4520` (sticker)          | приглушённый олива `#2c2412`             |

Особенности:

- **Task open — единственная светлая карточка** в теме. Тёмный текст на ней (`#444444`) обеспечивает контраст. Это намеренная асимметрия: открытая задача наиболее частый элемент на экране, и светлый фон делает её самой «лёгкой для скана».
- **Plan имеет два смежных оттенка фиолетового** для open vs authorized. Сам тип фиолетовый, оттенок различает состояние.
- **Memo open** — тёплый жёлтый, без бордера; sticker-эффект достигается контрастом цвета (см. §6.1).
- Цвет открытой работы (оранжевый) и закрытого тикета (cyan) — намеренно противоположны на круге, чтобы две самые активно меняющиеся группы не путались.

## 5. Кодирование ОТКРЫТОСТИ и СТАТУСА (уровни 2 и 3)

### 5.1. Открытость (уровень 2)

Открытость = смена hue фона (см. §4). Никаких полос, badge-ей или иконок для open/closed:

- **open** карточки имеют свой type-цвет (Task: `#d6d6d6`, Job: `#f59910` и т.д.).
- **closed** карточки имеют другой type-цвет того же типа (Task closed: `#367bf7`, Job closed: `#00a13c` и т.д.).

При этом тип сохраняется: open-job и closed-job обе «работа» (диспетчер опознаёт это по контексту и по counters), но мгновенно отличает «в работе» от «выполненной».

Plan — частный случай: и open, и closed/denied используют фиолетовую палитру, открытость различается оттенком (`#551b95` vs `#2e1f4f`) и через подстатус прогресса (см. §5.2).

### 5.2. Статус внутри открытости (уровень 3)

Статусы кодируются **4px полосой на левом крае** карточки в семантическом цвете. У карточки без подстатуса (просто open или просто closed) полосы нет — левый край = край фона.

| Статус                         | Применимость          | Полоса слева                              | Дополнительно                           |
|--------------------------------|-----------------------|-------------------------------------------|------------------------------------------|
| **none** (просто open/closed)  | Task / Job / Ticket / Plan | нет                                  | —                                        |
| **activeNow**                  | open Task             | 4px **success** (`#22c55e`)               | через `border-left`                      |
| **closeMe** (ожидает закрытия) | open Task             | 4px **info** (`#3b82f6`)                  | через `box-shadow inset`                 |
| **negative**                   | open/closed Task      | 4px **danger** (`#ef4444`)                | 25% danger-overlay в фоне                |
| **ticket red**                 | open Ticket           | 4px **danger** (`#ef4444`)                | через `box-shadow inset`                 |
| **ticket green**               | open Ticket           | 4px **success** (`#22c55e`)               | через `box-shadow inset`                 |
| **ticket blue**                | open Ticket           | 4px **info** (`#3b82f6`)                  | через `box-shadow inset`                 |
| **plan unknown**               | authorized Plan       | 4px **muted** (`#64748b`)                 | через `border-left`                      |
| **plan partial**               | authorized Plan       | 4px **warning** (`#f59e0b`)               | через `border-left`                      |
| **plan failed**                | authorized Plan       | 4px **danger** (`#ef4444`)                | через `border-left`                      |
| **plan complete**              | authorized Plan       | 4px **success** (`#22c55e`)               | через `border-left`                      |
| **alert** (серверная ошибка)   | любой                 | —                                          | danger-tint поверх + анимация `shake`    |
| **flash** (мигание)            | любой                 | —                                          | анимация `flash` (success)               |
| **updating** (loading)         | любой                 | —                                          | спиннер top-right через `:before`        |
| **dragging / dimmedOut**       | любой                 | —                                          | `opacity: 0.6`                           |
| **favorite**                   | любой Task            | —                                          | иконка-фон в `.content`                  |

Правила:

- Цвет полосы слева — всегда **семантический**, не цвет типа. Тип кодируется фоном, статус — полосой. Два независимых канала.
- В реализации полоса слева для разных статусов проходит через разные механизмы (`border-left` для activeNow и plan, `box-shadow inset` для closeMe, negative, ticket red/green/blue). Снаружи это незаметно — итоговый визуал 4px solid слева идентичен.
- closeMe в текущей реализации **статичен** (не пульсирует). Ранее было решение про пульсацию — отозвано.
- closed-карточка может иметь полосу статуса (например, `closed.negative`) — фон закрытый, полоса видна.

### 5.3. Маппинг open/closed на типы

| Тип    | open                                       | closed                                | Возможные status-полосы              |
|--------|--------------------------------------------|---------------------------------------|--------------------------------------|
| Task   | всё, кроме `.closed`                       | `.closed`                             | activeNow, closeMe, negative         |
| Job    | `.open`                                    | `.closed`                             | — (job не имеет подстатусов)         |
| Ticket | `.red` / `.green` / `.blue` / без класса   | `.closed`                             | red→danger, green→success, blue→info |
| Plan   | `.authorized` без `.complete` и `.failed`  | `.authorized.complete` / `.authorized.failed` / `.denied` | unknown→muted, partial→warning, failed→danger, complete→success |
| Memo   | `.open`                                    | `.closed`                             | — (memo не имеет подстатусов)        |

## 6. Исключения и вложенные карточки

### 6.1. Memo open — стикер

Memo концептуально отличается от Task/Job/Ticket/Plan: это бумажный стикер на доске, заметка для будущего себя. У него нет дедлайнов и нет подстатусов выполнения по бизнес-логике.

| Свойство             | open memo                             | closed memo                              |
|----------------------|---------------------------------------|------------------------------------------|
| Фон                  | warm yellow `#5a4520`                 | приглушённый олива `#2c2412`             |
| Бордер               | none (как у всех карточек modern)     | none                                     |
| Текст                | `--text-primary`                      | `--text-secondary`                       |
| Левая полоса         | нет (memo не имеет подстатусов)       | нет                                       |

Это исключение обосновано предметной областью (заметка, а не оперативная единица) и не нарушает иерархию — тип и открытость кодируются по общим правилам §4/5.1.

### 6.2. Nested карточки (TaskLink, TicketLink внутри Memo)

`MemoCard` рендерит markdown с упоминаниями задач и заявок (`[[T123]]`, `[[I456]]`) — они отображаются как `span.userTaskLink` / `span.userTicketLink` ВНУТРИ memo.

Правила nested:
- **Тип кодируется фоном** упомянутой карточки — те же `--TYPE-bg-open / --TYPE-bg-closed` токены.
- **clip-path** `--cut: 3px` (вместо 7px у основных карточек) — пропорциональный срез угла, единый визуальный язык.
- **Бордер** отсутствует (как у обычных карточек modern).
- **Статусы nested-карточек** считываются как closed/active. closeMe / negative для упоминаний не показываются (избыточный шум в memo).

## 7. Подсветка карточек (hover / parent / child)

В modern подсветка реализована через **инверсию** карточки: фон заменяется ярким семантическим цветом, текст становится тёмным. Это противоположность outer-ring-стратегии, которую можно увидеть в classic.

| Состояние   | Фон при подсветке             | Цвет текста        |
|-------------|--------------------------------|---------------------|
| hovered     | `--sem-success-strong` (`#4ade80`) | `--text-inverse` (`#0a0d12`) |
| parentTask  | `--sem-warning-strong` (`#fbbf24`) | `--text-inverse`            |
| childTask   | `--sem-info-strong` (`#7ca5ff`)    | `--text-inverse`            |

Бордера у подсвеченной карточки нет (`--item-*-border: transparent`). Эффект — карточка визуально «выпрыгивает» из ленты яркой плашкой с инвертированным текстом, не привлекая взгляд к контурам.

Реализация: правила в `UserCell.css` ставят `background / border-color / color !important` через токены `--item-{hover,parent,child}-{bg,border,color}`. В classic эти токены — `palegreen / darkgoldenrod / deepskyblue` с тёмным текстом; в modern — bright-семантика с inverse-текстом.

`transition: background 0.2s ease` на `li.userItem` (определена в modern-теме) даёт плавный переход.

Только одна подсветка одновременно (parent взаимоисключает hover, child взаимоисключает hover).

## 9. Типографика

| Параметр             | Значение                                            |
|----------------------|-----------------------------------------------------|
| Базовый шрифт        | `Helvetica Neue, Helvetica, Arial, sans-serif`     |
| Моноширинный         | `"JetBrains Mono", "SF Mono", Menlo, Consolas`     |
| `--font-size-base`   | `12px`                                              |
| `--font-size-sm`     | `11px` (footer, мелкие метки)                       |

Тема использует тот же базовый шрифт что и classic (Helvetica) — отличия в плотности (12px) и геометрии. AntD-конфиг манифеста темы (`modern/index.js`) указывает Inter с fontSize 12.5px для AntD-компонентов, что даёт небольшое разнообразие в поверхностях типа Modal/Dropdown.

## 10. Геометрия

| Параметр              | Значение  | Заметки                                   |
|-----------------------|-----------|--------------------------------------------|
| `--radius-sm`         | `1px`     |                                            |
| `--radius-md/lg/xl`   | `2px`     | минимальные, почти прямые углы             |
| `--space-1..5`        | `2/4/6/10/14 px` | плотная сетка                       |
| `--border-width-thin` | `0`       | бордеров у карточек нет                    |
| `--border-width-thick`| `0`       |                                            |
| Толщина status-stripe слева | `4px` (карточка), реализация varies |                                  |
| `--cut` для clip-path | `7px` (карточка), `3px` (nested) | визуальная подпись Modern    |
| Padding `.content`    | `1px 0 1px 3px` | плотный, текст ближе к левому краю   |
| Margin между карточек | `2px`     | задан в UserCell.css                       |

clip-path-формула (полигон с срезанным правым нижним углом):
```css
clip-path: polygon(
    0 0,
    100% 0,
    100% calc(100% - var(--cut)),
    calc(100% - var(--cut)) 100%,
    0 100%
);
```

## 11. AntD интеграция

Применяется `theme.darkAlgorithm` — массовое перекрашивание ~600 внутренних AntD-токенов. Поверх (`src/Themes/modern/index.js`):

```js
{
  algorithm: antdTheme.darkAlgorithm,
  token: {
    colorPrimary:    '#3b82f6',  // = --sem-info
    colorSuccess:    '#22c55e',
    colorWarning:    '#f59e0b',
    colorError:      '#ef4444',
    colorInfo:       '#3b82f6',
    colorBgBase:     '#0a0d12',
    colorBgContainer:'#1c2230',
    colorBgElevated: '#2a3142',
    colorText:       '#f1f5f9',
    colorBorder:     '#475569',
    borderRadius:    0,
    fontFamily:      'Inter, ...',
    fontSize:        12.5,
    controlHeight:   28,
  }
}
```

AntD-цвета берутся из той же палитры, что и кастомный CSS. Семейство `colorBg*` чуть темнее, чем `--surface-page` в кастомном CSS (`#0a0d12` vs `#2c2c2c`) — это намеренно, чтобы AntD-overlay'и (Modal, Dropdown) выглядели «глубже» основной поверхности.

## 12. Прочие компоненты

### 12.1. UserCellHeader (счётчики над колонкой)

- Счётчики — цвет = цвет соответствующего фона типа:

- [x] Тип карточки кодируется ТОЛЬКО цветом фона. Никаких полос, иконок или рамок для типа.
- [x] Все 5 типов имеют различимый hue фона.
- [x] Closed-вариант каждого типа отличается от open отдельным hue.

## 14. Структурные правки CSS-компонентов

Реализация темы потребовала изменений за пределами `tokens.css` через **двух-токенную схему** (один токен решает результат для classic, другой — для modern):

1. **Task.css** — `li.userTask.activeNow` использует `border-left: var(--task-active-now-border-left)` + `box-shadow: var(--task-shadow-inset), var(--task-active-now-shadow)`. В classic это даёт 4px зелёный border-left (как раньше), в modern — успешную полосу через тот же механизм. `closeMe` управляется через `--task-shadow-closeMe` + опциональную `--task-closeMe-animation` (в текущей реализации modern animation не активирована).
2. **TicketCard.css** — red/green/blue правила используют пары `var(--ticket-X-border)` + `var(--ticket-X-shadow)`. В classic — 2px-обводка по периметру, в modern — 4px box-shadow inset слева. `li.userTicket` получает фон через `var(--ticket-bg-open)` (новый токен).
3. **PlanCard.css** — 4 правила прогресса используют пары `var(--plan-stripe-X-border-left)` + `var(--plan-stripe-X-shadow)`. В classic — 8px цветной border-left, в modern — 4px того же цвета в семантической палитре.
4. **UserCell.css** — правила hovered/parent/child используют `--item-{hover,parent,child}-{border,bg,color}`. Classic заливает фон/border (palegreen/lime), modern инвертирует — яркий success/warning/info фон + `--text-inverse`.
5. **CreateItemButton.css** — hover-правила вместо литеральных цветов используют `var(--TYPE-bg-*)` и `var(--TYPE-text-*)`, что сохраняет визуальную связь между кнопкой и типом, который она создаёт.

Принцип: **компонентные CSS не содержат `[data-theme=...]`-селекторов** — всё решается через токены. Селекторы `[data-theme="modern"]` живут только в `src/Themes/modern/tokens.css`, и только там, где правило неустранимо темо-специфично (например, clip-path, который не имеет смысла в classic).

## 15. История решений

1. **Plan progress на 4px полосе слева** — реализовано через двух-токенную схему `--plan-stripe-X-border-left`. Plan имеет фиолетовый фон (`#551b95`); progress-полоса слева добавляется поверх него.
2. **Приоритет — точки + цветной текст** (`midPriority` зелёным, `hiPriority` красным). Соответствующие токены в modern закомментированы — наследуются classic-defaults. Решение «только точка» отозвано.
3. **activeNow — статичная 4px полоса, без пульсации**. Это перманентное состояние, не призыв к действию.
4. **closeMe — статичная 4px info-полоса, без пульсации**. Ранее принятое решение про анимированную пульсацию отозвано в текущей реализации (`--task-closeMe-animation` не активирован).
5. **Memo open остаётся sticker** — тёплый жёлтый фон без рамки/бордера, без подстатусов.
6. **Ticket red/green/blue → 4px полоса слева** через box-shadow inset (без 2px-обводки по периметру).
7. **clip-path-срез нижнего правого угла** — стилистическая подпись modern, единая для основных карточек (7px) и nested (3px).
8. **Hover/parent/child через инверсию** (яркий фон + тёмный текст) вместо outer ring — карточка чётче «выпрыгивает» из ленты, фон типа в момент подсветки уступает место семантическому маркеру.
9. **Counters привязаны к цветам типов** — диспетчер видит цифру в том же цвете, что и карточки, которые она считает.
10. **CreateItemButton hover — точное совпадение с целевой карточкой** — кнопка выглядит как мини-превью того, что будет создано.

При расхождении документа и реализации правится **то, что отстало** — приоритет за тем, что фактически рисуется на экране.
